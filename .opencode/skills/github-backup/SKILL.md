# github-backup: страховка в GitHub

Всё настроенное и сделанное должно оставаться при ученике: рабочий каталог
уходит в его приватный репозиторий GitHub. Ключ - `GITHUB_TOKEN` из `.env`
(значение никогда не печатай и не отправляй в чат).

## Шаг 1. Проверки

- `GITHUB_TOKEN` в `.env` (загрузка как в fal-images: `set -a; . ./.env; set +a`).
  Нет ключа - скажи, где взять, и жди. Нода ключа: классический personal
  access token с галочкой `repo` (Developer settings → Personal access
  tokens → classic) - его хватает и на создание приватного репозитория, и
  на пуш. Если ученик принёс fine-grained токен и создание репозитория
  падает с ошибкой - попроси классический с правом `repo`.
- `git --version` доступен. Нет - предложи установить (пакет git, вместе с ним
  придёт Git Bash) и ставь только после «да» ученика.

## Шаг 2. Репозиторий (один раз)

Если remote `backup` уже настроен - сразу шаг 3.

1. Узнай логин ученика: `curl -s https://api.github.com/user -H "Authorization: Bearer $GITHUB_TOKEN"` - поле `login`.
2. Имя репозитория: если ученик не назвал - один вопрос, по умолчанию
   `course-backup`.
3. Репозиторий всегда приватный (там личные фото и документы) - не спрашивай.
   Проверь существование: `curl -s -o /dev/null -w "%{http_code}" https://api.github.com/repos/<login>/<имя>`. 404 - создай:
   `curl -X POST https://api.github.com/user/repos -H "Authorization: Bearer $GITHUB_TOKEN" -d '{"name":"<имя>","private":true}'`
4. Подключи remote (токен останется в `.git/config` локально, на машине
   ученика - там же, где `.env`; наружу его не показывай):
   `git remote add backup https://<GITHUB_TOKEN>@github.com/<login>/<имя>.git`

Создание репозитория и первый пуш показывай ученику заранее: что уходит,
куда уходит.

## Шаг 3. Что бэкапим

Весь рабочий каталог, кроме:

- `.env` - секреты, в репозиторий не попадают никогда;
- `node_modules/`;
- любых фото и видео: jpg, jpeg, png, webp, gif, heic, bmp, tiff, svg,
  mp4, mov, webm, avi, mkv и подобные - картинки пересоздаются промптом,
  видео собирается из клипов, исходники остаются у ученика;
- любых файлов больше 10 МБ.

Всё исключённое добавь в `.gitignore` и перечисли в отчёте: что и почему
не ушло. Медиа нет - репозиторий остаётся маленьким и живёт годами.

## Шаг 4. Коммит и пуш

```sh
git init                                    # если репо в каталоге ещё нет
git branch -M main
git add -A
git commit -m "бэкап <дата>"
git push backup main
```

Ошибки пуша могут вывести remote URL вместе с токеном: показывая ошибку
ученику, замени токен на `***`.

## Шаг 5. Отчёт

Ссылка на репозиторий, сколько файлов ушло, что пропущено и почему.
Предложи ритм: бэкап раз в неделю вместе с «проверь и настрой своё
окружение» - страховка работает, только когда регулярная.
